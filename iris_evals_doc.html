Installation — from GitHub to any machine

iris-evals is a private Python package hosted on GitHub. It is not on PyPI. Every agent project installs it directly from the repo.

Step 1 — Add to requirements.txt in every agent

txtrequirements.txt — inside each agent project
# agent dependencies
fastapi==0.115.0
uvicorn==0.30.0
httpx==0.27.0
a2a-sdk==0.3.26

# iris-evals — installed from private GitHub repo
iris-evals @ git+https://github.com/applexus/iris-evals.git@v1.0.0
💡

@v1.0.0 pins to a specific tagged release. When iris-evals is updated, agents choose when to upgrade by changing the tag — no agent breaks automatically.

Step 2 — Install on a new laptop

bash
# Inside any agent project folder
pip install -r requirements.txt

# Or install iris-evals alone
pip install git+https://github.com/applexus/iris-evals.git@v1.0.0

All Questions — iris-sap-agent-skill interview

The skill asks exactly 8 questions in order, one at a time. Q4 and Q5 are skipped when Q3 = Deterministic. Everything else is auto-generated silently.

Q1

Agent name and description

"What is the name of this agent and what does it do?"

Give: (1) agent name in kebab-case — e.g. iris-ap-p111-duplicate-invoice-detection
(2) One sentence describing what it does for Joule users.

Q2

Domain module and skill names

"What is the Python domain module name, and what are the 2–4 skill names?"

Domain module: folder under project root — e.g. accounts_payable, treasury
Skills: snake_case names — e.g. view_line_items, validate_vendor_payment

Q3

Deterministic or Non-deterministic?

"Should this agent be deterministic (no LLM) or non-deterministic (with LLM)?"

1 — Deterministic — keyword/regex routing, zero LLM tokens, exact outputs. Best for structured SAP data retrieval.
2 — Non-deterministic — LLM ReAct loop, dynamic tool selection, handles open-ended queries.

⚠ If Deterministic → Q4 and Q5 are skipped. Jump to Q6.

Q4

LiteLLM routing? (only if Q3 = Non-deterministic)

"Do you want LiteLLM as your LLM proxy/router?"

1 — Yes — all LLM calls through LiteLLM, cost tracking, model switching via env var, retry/fallback.
2 — No — LLM calls go directly to SAP AI Core.

Q5

LangGraph checkpointing? (only if Q3 = Non-deterministic)

"Use LangGraph with Postgres-backed checkpointing for this agent's reasoning loop?"

1 — Yes — StateGraph + AsyncPostgresSaver, resumable mid-conversation across restarts.
2 — No — plain while-loop ReAct, no external checkpoint store.

Q6

Redis response cache?

"Do you want Redis response caching?"

1 — Yes — caches skill results by session + intent key, reduces repeat OData calls. Follow-up: cache TTL in minutes (default: 10).
2 — No — fetch fresh data from SAP every time.

Q7

Joule integration?

"Do you want Joule capability files so this agent can be invoked from SAP Joule?"

1 — Yes — generates full joule/ folder (da.sapdas.yaml, capability, scenarios, functions). Follow-ups: BTP destination name + 3–5 trigger phrases.
2 — No — skip Joule files.

QE

Q_EVAL — iris-evals eval types (always asked, never skipped)

"Which evaluation types does this agent need? (iris-evals)"

Choose one or more by number, e.g. 1, 6 or 1, 2, 6 or all:

1 — deterministic
Exact verdict match. Pass rate = 100% required. Rule-based agents (P1.11, P2.5).
2 — probabilistic
Accuracy/F1 ≥ 85%. Classification/triage agents (P1.2).
3 — llm_as_judge
Claude scores quality with rubric ≥ 3.5/5. Auto-reply or summary agents.
4 — agent_as_judge
Another A2A agent evaluates via A2A protocol. Complex SAP domain workflows.
5 — trace
Correct SAP tools called in right order. Multi-step workflow agents.
6 — safety ★ always
PII leaks, injection blocking. Pass rate = 100%. Every agent should include this.
7 — performance
Latency p50/p95. p95 ≤ 5000ms. SLA-sensitive agents.
💡

Quick picks: Rule-based → 1, 6  |  Triage → 2, 3, 6  |  Multi-step SAP → 1, 5, 6  |  SLA-critical → 1, 5, 6, 7

What the skill auto-generates from your answer: x_evals block in agent-card.json → startup self-eval + background loop in app.py → /health/evals CI gate endpoint → iris-evals in requirements.txt. Zero eval files needed in your agent project.

Pythonapp.py — eval block auto-inserted by skill
import asyncio
from iris_evals import run_self_eval, self_eval_loop

AGENT_URL = "http://localhost:8080"

@app.on_event("startup")
async def startup_self_eval():
    report = await run_self_eval(agent_url=AGENT_URL)
    if not report.overall_passed:
        logger.warning("[IRIS EVALS] %s", report.summary)

@app.on_event("startup")
async def start_eval_loop():
    asyncio.create_task(
        self_eval_loop(agent_url=AGENT_URL, interval_seconds=300)
    )

@app.get("/health/evals")
async def eval_health():
    report = await run_self_eval(agent_url=AGENT_URL)
    return {"passed": report.overall_passed, "summary": report.summary}

All 7 Eval Types — what each one checks

1. Deterministic

Exact verdict match

Sends known inputs from the golden dataset. Agent must return the exact expected verdict every time. Pass rate must be 100%.

expected: DUPLICATE → got: DUPLICATE ✓
Used by: P1.11, P2.5
2. Probabilistic

Accuracy / F1 score

Runs many classification cases. Computes accuracy, precision, recall, F1 across all categories. Threshold is 85% accuracy.

accuracy ≥ 85% macro_f1 ≥ 0.80
Used by: P1.2 mailbox triage
3. LLM as Judge

Claude scores quality

Agent's free-text response is sent to Claude with a rubric (5 criteria, 1–5 scale). Weighted average must pass threshold of 3.5.

rubric score ≥ 3.5 / 5.0
Used by: P1.2 (auto-reply quality)
4. Agent as Judge

Another A2A agent evaluates

A second specialized SAP agent acts as evaluator via A2A protocol. For cases where SAP domain knowledge beyond Claude is needed.

judge_agent verdict = PASS
Used by: complex SAP workflow agents
5. Trace

Correct SAP tool sequence

Verifies the agent called the right SAP tools in the right order. Uses OpenTelemetry spans. Catches routing and orchestration bugs.

tools_called == expected_tools
Used by: multi-step SAP agents
6. Safety

No PII, no injection

Checks for PII leaks in responses, stack trace exposure, prompt injection attempts, and correct blocking of unsafe inputs. Always 100% required.

pass rate must be 100%
Used by: all agents
7. Performance

Latency histogram

Measures actual response time for every test case. Computes p50 and p95 latency. Fails if p95 exceeds the agent's threshold.

p95 latency ≤ 5000ms
Used by: SLA-sensitive agents

Runtime Flow — what happens after install

On every agent startup

1

uvicorn starts — app.py loads

BTP starts the agent process. @app.on_event("startup") fires before the agent accepts any real traffic.

2

run_self_eval() reads the agent card

Reads .well-known/agent-card.json from disk — no HTTP call. Finds x_evals.evaluators: ["deterministic", "safety"].

3

iris-evals loads from its built-in registry

Looks up the agent name in AGENT_REGISTRY. Loads 7 golden records for P1.11 — no JSON files needed anywhere.

4

Agent calls itself via A2A

Sends each golden record as a real A2A message/send JSON-RPC call to http://localhost:8080 — identical to how Joule would call it.

5

Each evaluator checks the response

DETERMINISTIC: response["verdict"] == "DUPLICATE" ✓ or ✗
SAFETY: no PII patterns, no injection, correct blocking ✓ or ✗

6

Report logged — agent starts serving traffic

PASS → agent starts normally. FAIL → warning logged, /health/evals returns passed: false, CI can roll back.

7

Background loop runs every 5 minutes forever

Same eval re-runs silently while agent is live. Catches regressions from SAP config changes without any human trigger.

iris-evals ships inside each agent container. There is no separate iris-evals service on BTP. The library installs via requirements.txt when CF buildpack runs pip install.

What happens on each BTP deployment

1

cf push

CF buildpack runs pip install -r requirements.txt — pulls iris-evals from GitHub, installs inside the container.

2

Agent boots — startup eval fires automatically

Before serving traffic, agent calls itself with all golden records. If SAP is broken or the new code introduced a regression, it fails here.

3

CI calls /health/evals

passed: true → promote to production. passed: false → pipeline fails, previous version stays live.

4

Background loop monitors continuously

Every 5 minutes, evals re-run silently. SAP config drifts, vendor data edge cases, env issues — all caught automatically without waiting for a user to report a problem.

📦

iris-evals is never deployed as a separate service. It is a Python library that lives inside each agent's container — installed at pip install time, running inside the agent process. No extra BTP service, no extra CF app, no extra cost.
